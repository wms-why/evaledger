## 一句话结论

- **价格一分没动，动的是 checkpoint。** 1017 的高峰价还是每 1M token 输入 $0.30、输出 $1.20，非高峰 $0.15 / $0.60，缓存读 $0.006——和 0910 那张价卡逐字相同。这次发布不需要任何一轮预算讨论。
- **同一张价卡，换来的是一个更能干活的 Agent。** 11 项跑分全部来自 1017 这一篇公告自己的表格，而且表格第二列直接复述了上一版的成绩，所以「到底提升了多少」是可以并排读出来的，不用自己拼两张表。
- **所以：跑 Agent 和编程的流量，直接用；对海外旗舰，价差依然在，建议分层而不是全换。** GPT-5.6 sol 是 $4 / $20，Claude Opus 5 是 $5 / $25，Flash 无论高峰还是非高峰都便宜一个数量级。1017 让 Flash 更值，但没把旗舰的分量级抹平。

## 发布了什么

- **模型名没变。** API 上依然是 `deepseek-flash`；老别名 `deepseek-v4-flash` 和 `deepseek-v4-flash-vision-exp` 仍然可用，会被路由到新 checkpoint，并按 Flash 的价格计费。客户端一行代码都不用改。网页端和 APP 也已经同步切过去。
- **权重是公开的。** Hugging Face 和 ModelScope 上都有 `deepseek-ai/DeepSeek-V4.1-Flash-1017`，可以自己拉下来部署。
- **训练换成了带自反馈的强化学习**，主打从零把整个项目做出来——游戏开发、3D 建模这类需求都能接住，而且提示词轮次更少。官方说这一版的输出更短、任务跑得更快，称为「性能–费用的帕累托改进」；它自己的 DeepSWE v1.1 图表显示，同等或更好的通过率对应更低的单任务成本——但成本那一半是厂商画的图，当方向读，别当账单读。
- **针对大家真正在用的框架做了优化：** DeepSeek Harness、腾讯 CodeBuddy、WorkBuddy。想在新版模型上拿到最好体验，建议升级到 DeepSeek Harness 0.2.1-rc.1 及以上版本。
- **价卡原封不动。** 高峰 $0.30 / $1.20，非高峰 $0.15 / $0.60，缓存读高峰 $0.006、非高峰 $0.003，上下文 1,000,000 token，我们手上的资料里没有长上下文加价档。
- **顺带一提：** 同一篇公告把 DeepSeek 自家的 Search 与 Fetch 接口对所有用户开放，按千次计费；用 DeepSeek API 的用户在 DeepSeek Harness、Claude Code、Codex 里通过服务端工具调用它，目前免费到北京时间 2026 年 11 月 1 日 00:00（UTC 2026-10-31 16:00）。

## 成本

- **先说最要紧的一条：这次不用改预算。** 把它和 [0910 那篇发布稿](/zh/releases/deepseek-v4-1-flash) 并排看，价卡一个数字都没变——变的是模型本身。对已经在跑 Flash 的团队来说，这是一次「不加钱就能拿到的升级」。
- **给国内团队：错峰是最省事的一刀。** 高峰是 UTC 01:00–04:00 与 06:00–10:00，换成北京时间就是工作日的 09:00–12:00 和 14:00–18:00；其余时间一律 $0.15 / $0.60。夜间跑的批量任务、凌晨的日报汇总、周末的离线评测，天然就在便宜的那一档，中国法定节假日更是全天半价。改的只是一个 cron 的启动时间。
- **缓存读 $0.006 是高峰输入价的 2%，等于省 98%。** 客服工单要翻历史记录、内部知识库问答要反复带同一份文档、代码评审机器人每轮都要重读整个仓库——这类循环里，这一行基本决定账单。新 checkpoint 没有让缓存变贵，原来该怎么设计还怎么设计。
- **和同门 V4-Pro 的差距还是输入约 4 倍、输出约 3 倍**，高峰非高峰都一样（两边同时减半）。如果某些活儿非 Pro 不可，这次升级不改变那个结论，只是把便宜那一档的质量又往上抬了抬。
- **和海外旗舰的价差依然在数量级上。** GPT-5.6 sol 是 $4 / $20，Claude Opus 5 是 $5 / $25，Flash 是高峰 $0.30 / $1.20、非高峰 $0.15 / $0.60。1017 让 Flash 的性价比更好，但不会把 $0.30 的账单变成 $4 的账单。
- **上下文 1,000,000 token，没有额外档位。** 长提示词和短提示词一个价，不用为「把整份代码库塞进去」单独做预算。

## 跑分

- **11 项，同一篇厂商公告。** 这是 2026-10-17 发布稿里的那张表，我们转录了它：数字彼此自洽、出处可追，但它本质上是厂商口径，不是第三方复测。正确的读法是「DeepSeek 自己报的成绩」，而不是「榜单裁决」。
- **表格第二列就是上一版，所以能并排读。** Terminal-Bench 4.0 从 31.2 涨到 42.3，DeepSWE v1.1 从 74.2 到 77.0，ProgramBench 从 20.3 到 29.1，NL2Repo-Bench 从 65.4 到 68.2，Automation-Bench 从 54.8 到 60.5，Agents' Last Exam 从 31.8 到 35.4。真正跑 Agent 的团队，体感最明显的正是这几行。
- **每一行的口径都要看，否则容易横比出错。** Terminal-Bench 4.0 是用 Claude Code 框架测的，DeepSWE v1.1 用 Mini-SWE-V2，ZeroBench-main 是 Pass@5——这三个数不能和别的框架下测出来的数字直接比。HLE 记的是 42.6，来源另外标了纯文本子集上的 44.0；只报纯文本子集的模型，和它并不在同一条起跑线上。
- **两个 Apex 别搞混。** 这里的 72.1 是 Apex Bench v1.1，和 MathArena Apex 是两个不同的 benchmark，只是名字撞了。
- **带工具的几行是这次最亮的：** Chartography（带工具）83.0、BabyVision（带工具）92.5、ZeroBench-main（带工具）51.0。
- **横向看对比行。** Terminal-Bench 4.0 上，1017 领先 GLM 5.3 的 37.9 和 Kimi K3 的 12.6，和 GPT-5.6 sol 的 39.9 基本贴身，但离 Claude Opus 5 的 51.8 还有距离；HLE 那一列是 42.6，Kimi K3 是 43.5，GPT-5.6 sol 是 44.5，Claude Opus 5 是 56.3。空格一律读作「没报」，不是零分。
- **覆盖面提醒：** 1017 这张表没有覆盖我们追踪的全部 benchmark，GPQA、Codeforces、MathArena、CyberGym 这些列根本不在表里——空格是缺数据，不是差成绩。

## 该不该换

- **已经在用 Flash 跑 Agent 或编程：** 严格说不需要「换」——API 本来就在服务 1017。模型名、单价、SDK 调用方式全都没变，变的只是回给你的东西更好。要做的工作是复盘自己的 prompt 和工具链，不是改集成。
- **在用海外旗舰：** 价差还是数量级，所以建议分层而不是整体切换：出错代价高、一次错就要人工兜底的链路留给旗舰；量大、可重试、容错成本低的流量搬到 Flash。1017 出现之后，这个分层比上个月更容易向老板解释。
- **能错峰的活就错峰跑。** 把离线任务挪出那两个高峰窗口，账单直接减半，这是本文里投入产出比最高的一条建议。
- **会重复读同一份上下文的：** $0.006 / 1M 的缓存读把「长上下文」从负担变成可行方案——该上缓存的地方照旧上，不用因为换模型而重新设计。
- **想自建的：** 权重就在 Hugging Face 和 ModelScope 上，而且和 API 现在服务的是同一份。可以先用自己的机器把 11 项跑一遍，再决定要不要把生产流量迁过去。
- **什么会改变我们的建议：** 同一批 11 项的第三方复测。现在这些数字是厂商自己报的，那张「性能 vs 单任务成本」的图也是同一个厂商的。方向可信，账单不可信——所以真要搬流量，先在一条业务线上做小流量 A/B，用自己的评测集比，而不是拿公告表当验收标准。
