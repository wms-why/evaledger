## 一句话结论

- **2026-10-23，月之暗面官方账号发了一段 24 秒的预热视频。** 复古电脑终端风格，Kimi Code 的启动横幅上写着 `model: kimi k3.1`，模型正在写一个程序化 Three.js 3D 场景的代码——然后把它渲染出来。这个名字第一次出现在厂商自己的产品界面上：不是爆料，是官方。
- **模型已经在明面上被测了，只是还挂着代号。** Arena 竞技场上一个叫 `Kibitz` 的匿名模型当天出现，分词器等特征已被网友对上 K3.1。这正是 K3 走过的路径：先匿名上场，再放预告，几天后正式发布。
- **除名字之外，什么都还没确认，而这一页用「不写」来表达这一点。** 没有模型卡，没有 API 模型 ID，没有价格，没有跑分。所以这里不放价格表，也不放跑分表，正文也不许引用任何价格或分数。月之暗面真上线那天，这一页就地重写成带实时数据的完整分析。

## 已经能确认的

- **视频里有什么，逐帧看。** 一台复古 CRT 终端，Kimi Code 启动横幅上写着工作目录、`model: kimi k3.1`，状态栏 `thinking: high`。终端里敲进去的提示词是 *"Build a complex procedural 3D scene in Three.js."* 之后画面切到它产出的东西——一片粒子星云收束成 Three.js 预览窗里的建筑渲染，旁边是滚动生成的代码。整个片子没有任何口头或文字声明：不报参数、不报上下文、不报日期。
- **横幅里那个版本号要看清楚。** 终端在模型名旁边还打了一个 Kimi Code **客户端**的构建号，那是 CLI 的版本，不是 K3.1 的版本——两行挨着，很容易看串。
- **K3.1 正在 Arena 里以 `Kibitz` 为代号被测。** 这个匿名模型 2026-10-23 出现在竞技场，网友用分词器等特征比对，认定是月之暗面的下一代旗舰。Arena 是 K3 发布前被测的地方，出现在那里是发布前的常规动作，不是发布本身。
- **月之暗面自己的 API 模型列表（今天核对）。** 上面公开可调用的模型有四个：旗舰 `kimi-k3`、两个编程模型和一个通用模型，没有 K3.1。Kimi Code 的模型配置文档同样列了四个模型 ID，其中也没有 K3.1。预告片里出现名字，不等于你能调到这个模型。
- **它属于哪条产品线。** 当前的旗舰是 K3：2.8 万亿参数、原生多模态、100 万 token 上下文，权重以 Kimi K3 License 开源。K3.1 是这条线上的小版本。

## 到目前为止的时间线

四个信号，按顺序，其中只有最后一个出自月之暗面自己：

- **9 月下旬** —— API 平台上出现 `kimi-k3-1` 标识。属于二手报道，公开的模型列表上没有它。
- **2026-09-23** —— 内部配置片段流出，带着 `k3d1-agent` 字段，指向 Agent 模式和超长上下文选项。
- **2026-10-21** —— K3.1 出现在 Kimi Code 的模型切换配置里。
- **2026-10-23** —— 官方预告片，几小时后 Arena 上 `Kibitz` 上场。

节奏和 K3 一样：匿名上场 → 无字预告 → 过几天发布。关注此事的人普遍预期，Arena 上场后大约一周内官宣，也就是 10 月底这个窗口。这是预期，不是公告——月之暗面没有给出任何日期。同一篇报道把 K3.1 与智谱 GLM-5.5 并列为月底前有望发布的两款旗舰，其中只有 K3.1 已经放了预告。

## 网友实测说了什么

- **演示是视觉的，不是测量的。** 2026-10-22，多位网友发出据称是 K3.1 的鹈鹕渲染和 3D 动画，反馈集中在「效果很强」，有人评价可以和 GPT-6 Astra 有得一拼。
- **把它读成观感，别读成分数。** 画一只鹈鹕、做一段 3D 动画，是当代的茶壶测试：肉眼好判断，坏了也很明显。它说明不了跑一百个提示词的成功率，而且发出来的 demo 通常都是多次尝试里最好的那一次。
- **能力上的说法仍是说法。** 爆料指向三个提升方向：长程自主任务、游戏与 3D 代码、操作电脑。预告片展示的是第二个。第三个没有任何已发布的东西支撑——真要演示操作电脑，画面会是屏幕，而不是终端。

## 它会落在榜单的哪个位置

- **成本：今天无法回答，而且这是刻意的。** 等月之暗面公布费率，这一页会把它和站内其它模型放进同一张表——每 100 万 token 的输入、输出、缓存读单价，从厂商自己的定价页实时读取，再用这一行算出每月 100 万输入 + 50 万输出的开销。没公布的费率，我们不估。
- **跑分：K3 的数字是基线，不是 K3.1 的。** 我们手上已核验的当前旗舰成绩是 HLE 43.5、GPQA-Diamond 92.9、Terminal-Bench 4.0 的 12.6，以及 DeepSWE v1.1 的 67.5。这些属于 K3 的权重。K3.1 要有自己的测量才有自己的行——把上一版 checkpoint 的分数挪过来用，是这个站唯一不能犯的错。
- **那个被期待、也该被打折的数字。** 社区预期 K3.1 能进某个综合指数的全球前三，并成为首个在该指数上突破 50 分的国产模型，甚至希望到 55–60。这是期待，不是结果，也不是我们收录的基准。等厂商表格或第三方榜单给出真实数字，它们会进到这篇文章上方的跑分表里。
- **有一件事已经成立：** K3 是开源权重。如果 K3.1 走同一条路，权重会落到模型库上，自部署就变成一个选项——这是 API 定价页永远回答不了的那种成本问题。

## 该不该提前规划

- **别等。** K3 今天就能用，文档和跑分都是现成的；K3.1 现在只是一段预告加一个匿名上场。拿已经发布的东西去干活。
- **把模型 ID 写进配置。** 等 API ID 出现，换模型应该是一次配置修改，而不是一次重构。同时留好你自己的一小批回归提示词，上线第一天就跑一遍——小版本通常不改 API 形状，但行为仍可能漂移。
- **只盯两件事。** 真正的信号是 Kimi 平台上出现可调用的 API ID，以及定价页上多出那一行。今天满屏的报道，本质上是在重复同样那四个信号。
- **demo 回答不了的，正是两个真问题：可用性与性价比。** 可用性——K3 当初把集群打满、被迫暂停新订阅，K3.1 上线第一天 API 容量够不够；性价比——也就是这一页拒绝去猜的那个数字。
