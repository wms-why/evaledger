## 一句话结论

- **MiniMax M3.1 Flash 是每 1M token 输入 $0.15、输出 $0.60，2026-10-19 发布**——正好是 MiniMax M3 的一半，也是我们榜上有跑分证据的模型里最便宜的一个。
- **价格是平的，代价是少一条通道。** 没有长上下文加价档；和 M3 不同，它不接受 `service_tier=priority`。官方中文公告里的报价是 ¥1 / ¥4 / ¥0.1（输入 / 输出 / 缓存读，每 1M）。
- **能横向比的跑分只有 3 项，而且都是厂商自测。** DeepSWE v1.1 73.7、CyberGym 82.0、Agents' Last Exam 29.6，全部来自官方发布稿——出处正当，但不是第三方复测。

## 发布了什么

- **新一代 Flash，价格直接砍半。** 输入 $0.15 / 1M、输出 $0.60 / 1M，缓存读 $0.015，active，2026-10-19 发布。
- **官方同时给了人民币报价。** 美元是 $0.15 / $0.60 / $0.015，中文公告里是 ¥1 / ¥4 / ¥0.1（输入 / 输出 / 缓存读，每 1M）。
- **平价，但少了一样 M3 有的东西。** 没有长上下文加价档，价格不随提示词变长；但 M3.1 Flash 根本不接受 `service_tier=priority`，而 M3 接受，代价是标准价的 1.5 倍。
- **上下文 1,000,000 token，是输入加输出的总量。** MiniMax 的口径和多数厂商不同——这一点会直接影响你怎么切请求。
- **M3 还在售，$0.30 / $1.20**，正好是新模型的两倍，输入超过约 512,000 token 之后单价会翻倍。
- **缓存读 $0.015**，是输入价的 10%，省 90%。

## 成本

- **一半价钱，而且规则更简单。** $0.15 / $0.60 对 M3 的 $0.30 / $1.20，输入输出都是整一半。M3 在输入超过约 512,000 token 之后单价翻倍，M3.1 Flash 在我们手上的资料里没有长上下文档，价格不随长度变。
- **代价是 priority 通道。** M3 可以用 `service_tier=priority`，按标准价的 1.5 倍计费；M3.1 Flash 根本不接这个参数。所以如果你有延迟敏感、原本在买 premium 的流量，这不是「无痛替换」，而是「更便宜的标准档选项」。
- **缓存读是输入价的 10%：** $0.015 对 $0.15 的输入价。同一段上下文反复重发的场景，这一行就是 90% 的折扣。
- **和旗舰放在一起看，差距不是零头。** 输入 $0.15 是 Claude Opus 5 的 $5 的 33 分之一，输出 $0.60 是它 $25 的 42 分之一。
- **窗口是共享预算。** 1,000,000 token 是输入和输出加在一起的总量：提示词用了 600,000，留给回复的就只剩 400,000。

## 跑分

- **能和本页其他模型横向比的只有 3 项：** DeepSWE v1.1 73.7、CyberGym 82.0、Agents' Last Exam 29.6。另外还有第 4 项 BankerToolBench，我们对比的模型都没有这一项，所以它不会成为对比行。
- **这 4 项全部是厂商自测。** MiniMax 发布的是自己基础设施上跑出来的数字，出处明确、可追溯，但限定条件也必须一起说：它不是第三方榜单的复测。
- **3 个数字的形状更有意思。** CyberGym 82.0 说明安全工程能力不错，DeepSWE 73.7 和表里的旗舰行基本齐平，Agents' Last Exam 29.6 与对比模型处在同一区间。三个分数我们不平均，你的评测也不该平均。
- **覆盖面就是天花板。** 三项里有两项是 agentic / 编程类，推理、知识、数学一项都没有。如果你的产品是做问答而不是改文件，这张表几乎帮不上忙。
- **还有一件事榜单也回答不了：** 我们更大的注册表里还有更便宜的——GPT-6 luna，$0.10 / $0.50——但它在我们榜上一条可溯源分数都没有。「有证据的最便宜」和「最便宜」是两句话，这里说的是前者。

## 该不该换

- **在用 MiniMax M3 的：这是本系列里最好换的一次。** 新模型便宜一半、规则更简单；M3 还在，你要是需要 priority 通道或者 1.5 倍服务档，就继续留在 M3。我们手上没有能拦住你的能力证据。
- **在用旗舰、流量又大：** 输入便宜 33 倍、输出便宜 42 倍，这个差距值得跑一次实验。放 5% 流量到 M3.1 Flash 上，其余不动，用你自己的指标比，而不是拿厂商跑分当结论。
- **延迟敏感的话要特别注意：** M3.1 Flash 不接受 `service_tier=priority`。别默认它能顶替 M3 的 premium 通道扛住延迟要求——对延迟敏感的那部分流量来说，这是要放弃的东西，应该算进决策。
- **长提示词场景：** 窗口是 1,000,000 的总量（输入 + 输出），而且没有长上下文加价。按总量而不是只按输入来切请求。
- **在意独立证据的话：** 这个模型公开的证据很少，而且都是厂商口径。A/B 跑真实流量在这里比看榜单更有说服力——所以我们把分数和限定条件一起给你。
