# EvalLedger 后续路线图（P1–P3，2026-10-21 记录）

> 这份文档记录 **P0 之外** 的规划，P0（可信度）已先行落地。记录的目的是：讨论过的方向不丢失，后续按优先级逐条推进，而不是每次重新讨论。
>
> 每一条都写清楚 **为什么做**（要解决的真实问题）、**做什么**（可交付的功能）、**成功标准**（怎么判断做成了）。
>
> 优先级定义：
> - **P1** — 转化：让用户能快速选出适合自己的模型，并愿意再来一次。
> - **P2** — 差异化：拉开与 Artificial Analysis / OpenRouter 的差距，形成自己的护城河。
> - **P3** — 分发：让 EvalLedger 从「人看的网站」变成「Agent 可调用的数据服务」。

---

## 1. P1 —— 转化：从「查模型」到「帮用户选模型」

当前 EvalLedger 已有「模型发现 → 对比 → 成本估算 → 版本追踪」的基础链路。P1 的目标是把这些工具**串成一个完整的选型流程**，而不是再增加几个孤立页面。

### 1.1 选型流程的四个步骤

| 步骤 | 用户在做什么 | 站点要提供什么 |
| --- | --- | --- |
| 1. 描述任务 | 「找一个适合 Claude Code 的编程模型，月预算 $100」 | 自然语言输入（或结构化筛选器） |
| 2. 按真实约束筛选 | 编程基准、Agent 能力、价格、延迟、上下文长度、API 兼容性 | 多条件联合筛选 |
| 3. 得到推荐 | 「首选 / 低成本替代 / 高性能」三档 | 带**理由**的推荐，不是黑箱 |
| 4. 估算实际成本 | 输入输出比例、缓存命中率、每月任务量 | 落到具体月费的估算 |

> **注意**：第 1 步的自然语言解析需要模型能力。P1 阶段先用**结构化表单 + 预设场景**实现（成本低、结果可控），自然语言入口留到有模型 API 预算时再做。

### 1.2 三个最值得优先开发的功能

#### A. Best Value｜最佳性价比模型

不要只按价格或综合分排名，而是展示**质量—成本的权衡曲线**：

- 散点图：横轴每百万 token 成本，纵轴能力分（按专项榜，如 P0 的编程榜）
- 标出**帕累托前沿**（同等成本下表现更好的模型）
- 标出**被全面超越的模型**（同成本更差、同分数更贵）

**为什么**：这是「质量—成本权衡」的直接可视化，是当前站点完全缺失、而决策型用户最需要的一屏。
**预期价值**：提升用户从榜单进入对比工具的转化率。

#### B. Real Cost Estimator｜真实任务成本估算

从「每百万 Token 多少钱」升级为「**完成一次任务**多少钱」：

| 任务类型 | 计量单位 |
| --- | --- |
| 一次对话 | 1,000 次会话 |
| 一个代码任务 | 一次 PR / 一次 issue 修复 |
| 一份文档 | 一篇 3,000 字报告 |
| 一次 Agent 会话 | 一次完整任务（含重试） |

**为什么**：开发者真正关心的是「完成一次任务多少钱」，不是「这些 Token 多少钱」。
**预期价值**：让用户更容易理解成本差异，并形成回访习惯。

#### C. Should I Upgrade?｜模型升级决策

对新旧模型给出：

- 能力变化（分项对比，不只是总分）
- 成本变化（迁移后月账单变化）
- 性能变化（延迟 / 吞吐 / 上下文）
- 迁移建议（什么时候该升，什么时候不值得）

配套：**用户可订阅自己关注的模型系列**，在价格或成绩发生变化时接收通知。

**为什么**：把一次性搜索访问转化为持续使用。
**实现前提**：P0 的价格窗口（生效/失效时间）已经把「调价」变成了可判定的事件，通知才能准确触发。

### 1.3 指标

| 指标 | 目的 |
| --- | --- |
| 榜单 → 对比器点击率 | 衡量模型发现功能是否有效 |
| 对比器完成率 | 衡量用户能否真正完成选型 |
| 成本计算器使用率 | 衡量工具是否解决实际问题 |
| 搜索访问后的交互率 | 判断 SEO 流量质量 |
| 7 日 / 30 日回访率 | 衡量版本追踪与关注功能是否有价值 |

## 2. P2 —— 差异化：拉开与同行的差距

当前赛道竞争已经不只是「谁收录的模型多」。Artificial Analysis 同时展示智能指数、单任务成本、输出速度、首 Token 延迟和完整响应时间；OpenRouter 有真实使用量排行榜和模型使用趋势。

**EvalLedger 需要选择自己的差异化方向**，而不是全部照做。

| 优化方向 | 具体功能 | 优先级 |
| --- | --- | --- |
| 推理性能 | 首 Token 延迟、输出速度、总响应时间 | 高 |
| Agent 场景 | 编程 Agent、终端操作、长任务完成率 | 高 |
| 真实使用情况 | 热度趋势、模型增长、近期关注度 | 中 |
| 供应商比较 | 同一个模型在不同 API 服务商的价格与性能 | 高 |
| 订阅套餐比较 | Coding 套餐与按 Token 付费的盈亏平衡点 | 中 |
| 开放数据接口 | JSON、CSV、公开 API、MCP Server | 中高 |

### 2.1 优先方向一：供应商维度

同一个模型可能通过**官方 API、云平台、第三方路由商**提供服务。模型本身相同，**并不意味着价格、延迟和可用性相同**。

要做的：同一个模型 × 多个供应商的对比（价格、延迟、可用性），并明确标注「官方直连」与「第三方路由」的差别。

> 呼应 P0-②：价格已经拆成 Input / Output / Cached / 渠道 / 档位 / 核验时间，供应商维度是这套字段的自然延伸。
> Artificial Analysis 的供应商排行榜已经体现了这种比较方式。

### 2.2 优先方向二：Agent 真实成本

传统 Token 计算器只能回答「这些 Token 多少钱」，开发者真正关心的是「**完成一次任务多少钱**」。对编程 Agent 而言，重试、上下文累积、工具调用、缓存命中都会改变实际成本。

要做的：把**任务成功率、平均任务成本、执行时间**放在一起。

> 这是 1.2-B 的深水区版本：P1 做「按预设场景估算」，P2 做「按真实任务数据校准」。

### 2.3 SEO：不要只靠批量生成模型页面

首页已有模型详情、模型对比、发布文章、基准测试和最佳模型等页面入口——这是很好的 SEO 基础，但应围绕**用户的实际搜索意图**扩展。

**优先级 A —— 高购买意图与高决策意图关键词**

- Best LLM for coding
- Cheapest LLM API
- Claude vs GPT API cost
- Best model for coding agents
- LLM API pricing comparison

> 落地页必须提供**真实比较表、成本估算或可交互工具**，而不只是文字介绍。

**优先级 B —— 模型版本与迁移关键词**

- Model A vs Model B
- Model A alternative
- Model A price change
- Model A vs previous version

> 将版本差异、价格变化和迁移建议自动关联起来。

**优先级 C —— 程序化 SEO 与开放数据**

- 模型 × 评测项目
- 模型 × API 供应商
- 模型 × 使用场景
- 可被 Agent 读取的结构化模型数据

> **只有在页面有独立、有价值的数据时才生成**，避免制造大量只有模型名称不同的薄内容页面。

**每个页面的基础要求**：清晰的更新时间、规范化 URL、结构化数据（JSON-LD）、指向原始来源的链接；并确保历史版本页面不会被错误地当成当前版本。

## 3. P3 —— 分发：成为 Agent 原生的数据服务

开发者现在不仅通过浏览器查模型，也会直接让 Coding Agent 帮自己选模型、检查预算和比较版本。

### 3.1 建设顺序

1. **公开、版本化的 JSON 数据** —— 模型列表、评测成绩、价格、来源和更新时间。先解决机器可读性。
2. **MCP Server** —— 让 Claude Code、Codex 等 Agent 直接查询模型、比较价格、检索基准测试。
3. **模型选择 API** —— 接受任务类型、预算、延迟上限等条件，返回带**依据和置信度**的候选模型。
4. **自动化监控** —— 允许用户关注模型、价格和基准测试变化，并在触发条件时接收通知。

### 3.2 关键判断

> **MCP Server 本身不是护城河。** 真正有价值的是**数据可靠性、可追溯的历史记录**，以及 Agent 可以直接执行的选型工作流。
>
> 这也是为什么 P0 排在前面：没有可信的数据，开放接口只会放大错误。

## 6. 一句话总结

> EvalLedger 当前最值得投入的不是「再增加 500 个模型」，而是把已经收集到的数据变成用户可以信赖的决策结果。
>
> - 短期（P0，已完成）：把排名、价格和来源做准。
> - 中期（P1/P2）：做出真正有用的最佳性价比、Agent 成本和模型升级决策工具。
> - 长期（P3）：让 EvalLedger 成为 Coding Agent 和其他 AI Agent 选模型时可以直接调用的数据服务。
>
> 如果只能选择一个功能作为下一步的主攻方向，应选 **Best Value + Agent 任务成本估算**——它既能利用现有数据，又直击开发者的实际痛点，比单纯扩大榜单更有机会形成产品差异化。
